# AI 生成提示词（可直接复制）

## 使用说明

有三种投喂方式，推荐第三种：

| 方式 | 做法 | 适用 |
|---|---|---|
| A. 单轮 | 只发「提示词 A」 | 上下文窗口大、模型执行力强（Claude Sonnet/Opus、GPT-5 级） |
| B. 分阶段 | 先发 A，再依次发 B1~B6 | 大多数情况，质量最稳 |
| C. 文档 + 分阶段 | 上传 `01/02/03` 三份 md，再发 A + B1~B6 | 最推荐，细节不丢 |

**三个必须遵守的操作习惯**：

1. 每轮结束让它自己跑 `npm run build`，构建不过不许进入下一轮。
2. 每轮只做一个大模块，不要让它"一次生成 28 个页面"。
3. 发现偷懒（只画静态图、数据写死、按钮无反应），立刻用「提示词 D」纠正。

```
4 MR 虚实交互：设备管理、空间标定（三方式向导）、交互编排（时间轴编辑器）、远程协同、会话记录。
5 巡检运维：巡检计划、路线详情、巡检记录、缺陷管理（含 AI 识别置信度）。

【三维要求 · 这是项目的核心，不能糊弄】
用 Three.js 程序化生成整个园区，禁止加载任何外部模型文件：

【MR 要求 · 纯前端模拟，必须可信】

- 远程协同：左右双流，画笔/箭头/圈选/文字标注可绘制并"同步"到现场画面，可录制并生成会话记录。

【数据要求 · 这是最容易偷懒的地方】

- 用固定种子伪随机生成，保证每次刷新一致。

- 统计数字必须由明细聚合，不能两套数。
- 异常数据占 8%~12%：设备离线、订单逾期、缺陷未闭环、质检不合格、SLA 超时。
- 时间落在 2025-03-10 ~ 2026-10-19，有工作日规律，周末数据下降。
- 禁止出现"测试数据""demo""xxx""TODO""lorem ipsum"，禁止 1/2/3 递增编号。

【视觉要求】
深色科技风为默认，可切浅色。底色 #070B14，面板 #0E1526，主色 #22D3EE，辅助 #6366F1，成功 #34D399，警告 #FBBF24，危险 #F87171。

三维页用浮动毛玻璃面板（backdrop-blur 12px），不遮挡画面。

【工程约束 · 打包桌面端的前置条件】
- 必须 HashRouter（file:// 下可用），vite base 设为 './'。
- 禁止任何 https 外链资源，图片全部用 SVG 内联或 Canvas 程序化生成。

4. 不要生成 README 之外的额外说明文档。

```
