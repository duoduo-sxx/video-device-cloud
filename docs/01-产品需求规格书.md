## 1. 产品概述

### 1.1 一句话定位

面向园区 / 厂区 / 文保建筑 / 基础设施，提供「实景采集 → 三维复刻 → 模型治理 → 场景发布 → MR 虚实叠加交互 → 运维闭环」的一体化平台，同时承载**三维复刻技术服务**的全流程交付管理（服务目录、订单、交付物、验收）。

### 1.2 为什么是一个系统两个半边

产品名里同时出现「系统」与「技术服务」，说明它有两类使用者：

- **软件侧**：客户自有团队用平台管理三维资产、做 MR 内容、跑巡检运维。
- **服务侧**：服务商用同一平台承接建模订单，管理里程碑、交付物与验收。

因此导航上必须有 `技术服务` 一级模块，且与服务订单、交付物、知识库打通。这是本系统区别于普通"三维可视化大屏"的关键，不能省略。

### 1.4 目标用户

| 角色 | 真实岗位 | 核心诉求 | 使用频率 |
|---|---|---|---|
| 项目负责人 | 项目经理 / 业主代表 | 看进度、看精度、看风险，能对外汇报 | 每日 |
| 测绘工程师 | 航测 / 扫描作业员 | 派任务、传成果、查质检 | 每日 |
| 建模工程师 | 三维重建 / BIM 翻模 | 管资产、做轻量化、查偏差 | 每日 |
| MR 交互设计师 | 数字内容 / XR 开发 | 编排交互、标定、发布 | 每周 |
| 运维工程师 | 园区设备运维 | 巡检、报缺陷、接工单 | 每日 |

| 平台管理员 | IT / 系统管理员 | 组织、账号、权限、日志 | 每周 |
| 访客 | 客户 / 领导 | 看三维、看 MR 演示、只读 | 按需 |

### 1.5 设计原则

1. **三维优先**：任何页面都能一键跳转到对应三维视角，三维查看器是全系统的中枢，不是装饰。
2. **数据可信**：宁可少几个功能，也不能出现"总览显示 386 个模型、点进去只有 20 条"这类断层。
3. **状态完整**：所有列表必须有加载态、空态、异常态、超期/离线等边界态，且边界数据要真实存在（约占 8%）。
4. **可演示**：任何按钮点下去必须有反馈，不能出现"功能开发中"。
5. **桌面端友好**：不依赖浏览器地址栏、书签、外网 CDN，离线可用。

## 6. 非功能性要求（摘要，详见 03 文档）

| 类别 | 指标 |
|---|---|
| 首屏加载 | 生产构建后 < 2.5 s（本地） |
| 三维帧率 | 默认视角 ≥ 55 FPS，全图层开启 ≥ 40 FPS |
| 交互响应 | 点击到反馈 < 100 ms，路由切换 < 300 ms |
| 兼容 | Chrome 110+ / Edge 110+，1280×800 起，推荐 1920×1080 |
| 离线 | 断网后除三维底图外全部可用（无任何外网请求） |
| 体积 | 生产包 gzip < 8 MB（three 独立 chunk） |
| 可访问性 | 键盘可达，表单有 label，颜色对比度 ≥ 4.5:1 |

## 7. 明确的"不做"

为避免 AI 过度发挥，以下内容**本期不实现**：

1. 真实后端、真实登录鉴权（登录页可做，但为本地校验）
2. 真实地图瓦片、真实卫星影像（禁止调用任何在线地图 API）
3. 真实无人机/头显设备通信（无 WebSocket、无 MQTT）
4. 真实 WebXR 会话（保留能力检测与降级提示）
5. 真实 3D Tiles / OSGB 大模型加载（预留适配层，使用程序化模型代替）
6. 多语言（仅简体中文）
7. 支付、发票、合同电子签
8. 视频会议真实推流（用模拟画面）
9. Electron / Tauri 相关代码与配置
10. 单元测试（可选，不做强制要求）
