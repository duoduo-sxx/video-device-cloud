## 1. 产品定位

### 1.1 一句话定义

面向指挥中心、沉浸式展厅、智慧楼宇等空间的**统一智能控制与人机交互中台**：操作者通过语音、文字、快捷指令、平面图点选等多模态方式下达意图，系统完成意图解析、指令确认、设备与场景控制、任务调度、异常处置，并提供配套的技术服务保障闭环。

### 1.2 核心价值主张

| 价值 | 说明 |
|---|---|
| 一屏统管 | 多空间、多品类设备在一套界面内统一呈现与控制 |
| 意图直达 | 从"找按钮"变为"说需求"，自然语言直接驱动场景执行 |
| 过程可解释 | 每次指令都展示解析结果、影响范围、执行回执，可撤销、可追溯 |
| 异常有闭环 | 告警 → 处置 → 工单 → 服务评价，形成完整链路 |
| 沉浸体验 | 深色科技风、玻璃拟态、环境光反馈、焦点模式，降低长时间值守疲劳 |

### 1.3 产品边界说明

- 系统**不是**真实设备控制软件，所有控制动作均在本地 Mock 状态中生效。
- 系统**不是**通用 IoT 平台，不提供设备接入协议、驱动管理、边缘网关配置。
- 系统**不包含**真实语音识别与语音合成，语音交互为前端模拟（可录到音量级别用于波形，但不做 ASR）。
- 系统**不包含**桌面端外壳代码（Electron / Tauri），但构建产物必须能被桌面壳以 `file://` 方式直接加载。

## 2. 目标用户与典型场景

### 2.1 角色定义

| 角色 | 代号 | 职责 | 权限侧重 |
|---|---|---|---|
| 值班调度员 | `operator` | 日常值守、场景切换、事件处置 | 控制、告警处置、任务执行 |
| 技术运维工程师 | `engineer` | 设备维护、工单处理、远程协助 | 设备管理、工单处理、日志 |
| 中心主管 | `manager` | 全局态势、数据分析、人员与权限 | 全量只读 + 管理 |
| 访客/演示 | `guest` | 参观演示、只读浏览 | 只读，隐藏管理模块 |

### 2.2 典型场景

**S1 晨间开场（8:50）**
值班员进入总览，系统显示"晨间迎宾模式"待执行提醒 → 通过语音说"启动晨间迎宾" → 系统解析意图并展示将影响的 14 台设备 → 确认执行 → 进度条逐台执行 → 3 台成功、1 台超时 → 系统提示"投影阵列 A 无响应，是否转为工单" → 一键生成工单。

**S2 会议保障（14:20）**
主管在命令面板搜索"3F 多功能厅" → 进入空间视图 → 发现 CO₂ 浓度 1250ppm 超标 → 点击环境卡片"开启新风" → 设备详情抽屉滑出 → 调节新风档位至 3 档 → 系统记录审计日志。

**S3 夜间巡检（22:30）**
自动化规则触发定时任务 → 任务看板出现"夜间巡检"卡片并自动流转到"执行中" → 逐设备检查 → 发现 UPS 电池健康度告警 → 生成 P1 告警 → 值班员认领并处置 → 关闭告警，工单自动归档。

## 3. 功能架构总览

系统分为四层：

```
┌─ 体验层 ────────────────────────────────────────────────┐
│  沉浸式主控台（全局框架 / 命令面板 / 语音交互 / 焦点模式）    │
├─ 业务层 ────────────────────────────────────────────────┤
│  态势总览 │ 多模态交互 │ 设备控制 │ 场景编排 │ 任务自动化    │
│  告警处置 │ 技术服务   │ 数据分析                           │
├─ 支撑层 ────────────────────────────────────────────────┤
│  用户与权限 │ 审计日志 │ 系统设置 │ 通知中心 │ 知识库        │
├─ 数据层（Mock）──────────────────────────────────────────┤
│  静态种子数据 + 运行时状态 + 时序生成器 + localStorage 持久化 │
└─────────────────────────────────────────────────────────┘
```

## 5. 页面级详细需求

> 统一约定：每页必须包含 **加载态（骨架）→ 内容态 → 空状态 → 错误态** 四种状态；所有异步操作必须有按钮 loading；所有列表支持 URL query 同步筛选条件。

### P-01 登录页 `/login`

- **布局**：左右 55/45 分栏，左侧品牌区、右侧表单区（窄屏堆叠）。
- **左侧**：产品名（两行，主标 36px）、副标题、三条能力点（图标 + 文案）、背景动态网格与光晕、底部版本号。
- **右侧**：标题"登录控制台"、账号、密码（可切换明文）、记住我、登录按钮、分隔线、"演示模式"四个角色卡片（值班调度员 / 技术运维 / 中心主管 / 访客演示）。
- **交互**：点击角色卡 → 按钮进入 loading 800ms → 写入 token 与角色 → 跳转 redirect 或 `/`。
- **校验**：账号 4-20 字符、密码 ≥6；错误时输入框红框 + 下方文案。
- **演示账号**：`operator / 123456`、`engineer / 123456`、`manager / 123456`、`guest / 123456`。

### P-02 态势总览 `/`

- **布局**：12 栅格。第一行 5 张 KPI 卡（各 2.4 栏）；第二行左 8 栏"实时态势图"、右 4 栏"环境参数 + 设备健康度"；第三行左 5 栏"交互趋势"、中 4 栏"指令类型分布"、右 3 栏"实时指令流"；第四行左 7 栏"今日事件时间线"、右 5 栏"活跃会话"。
- **实时态势图**：SVG viewBox 1000×560，绘制 6 个空间矩形（带圆角、半透明填充、空间名），内部撒布设备圆点（在线青、离线灰、告警红闪烁）。悬停显示浮层（设备名/状态/快照指标），点击打开设备抽屉。右上角图例与"告警聚焦"开关。
- **实时指令流**：`setInterval` 4 秒插入一条随机指令（用户、指令文本、状态图标、相对时间），列表最多 12 条，超出移除末尾，新条目有 400ms 高亮背景渐隐。
- **数据刷新**：KPI 每 10 秒微幅变化并伴随数字滚动；趋势图静态。

### P-03 多模态交互中心 `/interaction`

- **布局**：左侧历史栏 260px（可收起）+ 中间会话区自适应 + 右侧解析面板 380px。
- **中间会话区**：
  - 顶部：会话标题"新建会话"、模型/引擎标识"ICE-Engine v2.4"、清空按钮。
  - 消息流：助手开场白（含 4 条能力示例）；每条用户消息下方跟随解析卡片与执行回执卡。
  - 输入区：快捷胶囊行、输入框（多行自适应 1-4 行）、左侧语音按钮、右侧发送按钮；下方提示"Enter 发送，Shift+Enter 换行"。
- **语音交互流程**（核心演示点）：
  1. 按住语音按钮 → 按钮外圈出现脉冲 + 12 根波形条随机跳动 → 文案"正在聆听…"。
  2. 松手 → 文案"识别中" → 300ms 骨架 → 逐字流式输出（每 40ms 一字）识别文本。
  3. 文本输出完毕后自动执行：追加解析卡 → 800ms 后追加回执卡。
- **解析面板**：识别原文（关键词高亮）、意图标识（如 `scene.start`）、置信度圆环（78%-97% 随机）、槽位表（键/值/来源）、命中规则、候选意图 Top3（含百分比条）。
- **确认策略**：影响设备 ≥5 台或意图属于 `emergency.*` 时，插入确认卡（影响设备清单 + 10 秒倒计时 + 确认/取消）。
- **回执卡**：图标 + 标题（"场景已启动"）+ 元信息（影响 14 台设备 · 耗时 8.4s）+ 失败项折叠列表 + 撤销按钮（5 秒后消失）。
- **可识别的 Mock 指令集**（至少 12 条规则，命中即返回预设解析结果）：
  | 用户说法 | 意图 | 动作 |
  |---|---|---|
  | 启动晨间迎宾 | `scene.start` | 执行场景 SC-001 |
  | 关闭所有投影 | `device.batchOff` | 批量关 6 台投影 |
  | 把 3F 多功能厅温度调到 24 度 | `device.setValue` | 空调设定值 |
  | 现在有哪些告警 | `alert.query` | 返回告警摘要卡 |
  | 查看 A 座 1F 设备状态 | `device.query` | 返回设备列表卡 |
  | 帮我建个工单 | `ticket.create` | 跳转创建向导 |
  | 进入应急指挥模式 | `emergency.start` | 高危确认 → 执行 |
  | 把亮度调高一点 | `device.adjust` | 相对调整 |
  | 昨天用了多少次场景 | `analytics.query` | 返回统计卡 |
  | 静音所有播报 | `system.mute` | 切换 TTS 开关 |

## 6. 数据模型定义

> 以下为 TypeScript 类型草案，实现时放入 `src/types/`。

```ts
// 空间
export interface Space {
  id: string;              // SP-01
  name: string;            // A座1F 沉浸展厅
  building: string;        // A座
  floor: number;           // 1
  area: number;            // 面积 m2
  capacity: number;        // 容纳人数
  map: { x: number; y: number; w: number; h: number }; // 平面图坐标（1000x560 基准）
  deviceCount: number;
  onlineCount: number;
}

// 设备
export type DeviceStatus = 'online' | 'offline' | 'warning' | 'maintenance';
export type DeviceCategory =
  | 'display' | 'audio' | 'lighting' | 'hvac'
  | 'sensor' | 'control' | 'network' | 'power';

export interface DeviceMetric {
  key: string;             // temperature / brightness / power
  label: string;           // 温度
  value: number;
  unit: string;            // ℃
  threshold?: { min?: number; max?: number };
  trend?: number[];        // 最近 12 点
}

export interface Device {
  id: string;              // DEV-0108
  name: string;            // 主投影阵列 A
  code: string;            // PRJ-A-01
  category: DeviceCategory;
  type: string;            // 激光投影机
  vendor: string;
  model: string;
  firmware: string;
  spaceId: string;
  ip: string;              // 192.168.30.21
  status: DeviceStatus;
  health: number;          // 0-100
  controlType: 'switch' | 'range' | 'level' | 'mode' | 'readonly';
  power: boolean;
  value?: number;          // 当前值（range/level）
  unit?: string;
  mode?: string;
  modes?: string[];
  metrics: DeviceMetric[];
  lastReportAt: string;
  installedAt: string;
  owner: string;
```

7. 布局适配最小窗口 1280×800，主设计基准 1440×900，1920 下不出现拉伸变形。
8. 支持浏览器后退/前进（Hash 路由天然支持）。
9. 不使用 `window.open` 打开新窗口，跳转用路由。
