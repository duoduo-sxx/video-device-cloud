### 一、角色

你是一位资深前端架构师 + 数据可视化工程师 + B 端交互设计师，擅长构建高信息密度的深色科技风控制台界面。请从零实现一个完整可运行的前端项目。

### 二、项目

项目名称：**沉浸式智能控制人机交互系统与技术服务**（Immersive Intelligent Control & HMI Platform）

一句话定位：面向指挥中心、沉浸式展厅、智慧楼宇的**统一智能控制与人机交互中台**。操作者通过语音、文字、快捷指令、平面图点选等多模态方式下达意图，系统完成意图解析、指令确认、设备与场景控制、任务调度、告警处置，并提供配套的技术服务（工单 / 远程协助 / 知识库）保障闭环。

**这是纯前端演示系统：没有任何后端，所有数据在前端 Mock，所有交互在本地状态中真实生效。**

### 三、绝对硬约束（违反任一条视为失败，请优先满足）

1. **纯前端**。不得生成任何后端代码、API 服务、数据库脚本、代理配置。
2. **不得引入任何桌面端依赖**。不要 Electron、不要 Tauri、不要 `window.electron`、不要 `require()`、不要 Node 内置模块（fs / path / child_process）。项目之后会被第三方打包成桌面端，所以只需保证"静态产物能被 `file://` 加载"。
3. **路由必须用 `HashRouter`**（不能是 BrowserRouter），`vite.config.ts` 必须设置 `base: './'`。这两条是为了让打包后的 `dist/index.html` 双击能直接打开。
4. **零外网依赖**。不引 CDN 字体、CDN 图标、CDN 图表库、在线图片。图标用 `lucide-react`，图片一律用 CSS/SVG 绘制，字体用系统字体栈。断网时必须完整可用。
5. **无真实请求**。不要 `fetch` 任何外部地址，不要 axios。所有数据来自本地 Mock 模块。
6. **TypeScript strict 模式**，不允许 `any`。
7. **视觉必须统一**。禁止使用 Ant Design / Element Plus / MUI 等现成 UI 库，所有基础组件自行实现（TailwindCSS + 少量 CSS 变量），否则视觉会散架。
8. **每个页面必须同时具备：加载骨架态、正常内容态、空状态、错误态**。缺一不可。
9. **所有列表/详情页的数据必须互相关联**（设备属于空间、场景引用设备、告警关联设备、工单关联设备或告警）。不能出现互不相干的孤立假数据。
10. **默认深色主题**，同时支持浅色主题切换并持久化。

#### 2) 态势总览 `/`

#### 3) 多模态交互中心 `/interaction`（核心演示页，务必做精）
三栏：历史会话 260px + 会话区 + 解析面板 380px。

**会话区**：
- 助手开场白，附带 4 个能力示例气泡
- 消息流：用户气泡右对齐（青色边框），助手气泡左对齐（面板色），每条用户消息后跟随「意图解析卡」和「执行回执卡」
- 输入区上方有 3-5 个快捷胶囊（如"启动晨间迎宾""查看当前告警""把亮度调高"），点击直接发送
- 输入框多行自适应，左侧语音按钮，右侧发送按钮

**语音交互模拟（必须完整实现这条链路）**：
1. 按住语音按钮 → 按钮外圈三层脉冲扩散 + 12 根波形条随机跳动（`scaleY` 动画）+ 文案"正在聆听…"
2. 松手 → 文案"识别中…" → 300ms 骨架 → 逐字流式输出识别文本（每 40ms 一个字）
3. 文本完成后自动提交：追加用户消息 → 追加解析卡 → 800ms 后追加回执卡
4. 再点击一次可中断当前识别

**解析面板**（每次指令后更新）：
- 识别原文，关键词高亮
- 意图标识（等宽字体，如 `scene.start`）+ 意图中文名
- 置信度圆环（78%-97%），颜色按区间变化
- 槽位表：槽位名 / 值 / 来源（语音 / 文本 / 上下文）
- 命中规则描述
- 候选意图 Top3，带百分比条

**确认与回执**：
- 影响设备 ≥5 台或意图为 `emergency.*` → 插入确认卡：影响设备清单（前 5 条 + 折叠）、10 秒倒计时、确认/取消
- 回执卡三态：成功（绿）/ 部分失败（琥珀）/ 失败（红），显示"影响 14 台设备 · 耗时 8.4s"，失败项可展开，成功后 5 秒内可"撤销"

**必须内置的指令规则（至少 12 条，命中即返回预设解析结果）**：
| 用户说法示例 | 意图 | 行为 |
|---|---|---|
| 启动晨间迎宾 / 打开迎宾模式 | `scene.start` | 执行 SC-001 |
| 关闭所有投影 | `device.batchOff` | 批量关 6 台投影 |
| 把 3F 多功能厅温度调到 24 度 | `device.setValue` | 空调设定值 |
| 把亮度调高一点 | `device.adjust` | 相对 +10% |
| 现在有哪些告警 | `alert.query` | 返回告警摘要卡 |
| 查看 A 座 1F 设备状态 | `device.query` | 返回设备列表卡 |
| 帮我建个工单 | `ticket.create` | 跳转创建向导 |
| 进入应急指挥模式 | `emergency.start` | 高危确认 → 执行 |
| 昨天用了多少次场景 | `analytics.query` | 返回统计卡 |
| 静音所有播报 | `system.mute` | 切换 TTS |

未命中规则时返回"未识别到可执行指令"，并给出 3 条建议。
缺参数时反问（如只说"启动会议模式"未说空间 → 反问"你要启动哪个空间的会议模式？"），用户补充后合并执行。

浅色主题对应：`#F5F7FB` / `#FFFFFF` / `#0F172A`，同色相降饱和。

**核心规则**：
- 颜色一律走 token，禁止组件内写死 hex
- 卡片 = `bg-panel` + `1px var(--border-strong)` + 内高光 `inset 0 1px 0 rgba(255,255,255,0.04)`，hover 边框提亮 + 上浮 1px

- 主按钮 = `linear-gradient(135deg,#22D3EE,#0EA5C6)` + 深色文字 `#04141B`
- 状态点 = 8px 圆 + 3px 同色 15% 光晕，告警态脉冲
- 表格：表头 `bg-panel-2` 13px/500 次文本色，行高 48px，hover `rgba(34,211,238,0.04)`
- 抽屉/模态：遮罩 `rgba(4,8,14,0.72)` + `backdrop-blur(8px)`
- 圆角：控件 6 / 卡片 10 / 面板 12 / 浮层 16 / 胶囊 999
- 间距基数 4px，常用 8/12/16/20/24/32
- 字体：`"PingFang SC","HarmonyOS Sans SC","Microsoft YaHei",sans-serif`；数字用 `"JetBrains Mono","DIN Alternate",ui-monospace`
- 字号：11/12/13/14(正文)/16/18/20/24/32/40(大数字)
- 动效：页面切换 220ms fade+上移 8px；卡片 stagger 40ms；抽屉 240ms `cubic-bezier(0.32,0.72,0,1)`；hover 150ms；数字滚动 800ms；告警脉冲 1600ms 循环
- 动画只用 transform / opacity
- 所有交互元素：`cursor-pointer` + hover 态 + 可见 focus 轮廓 + `aria-label`

**三态**：骨架屏与真实布局同构（shimmer）；空状态 = 64px 线图标 + 主文案 + 辅助文案 + 主按钮；错误态 = 红色图标 + 摘要 + 重试按钮。

**响应式**：最小 1280×800 不出现横向滚动与重叠；基准 1440×900；1920 下内容不拉伸变形（用 max-width 容器）。
