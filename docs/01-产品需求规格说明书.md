## 1. 产品概述

### 1.1 一句话定位

面向企业的**数据流转中枢**：把分散在本地机房、边缘节点、公有云与私有云之间的数据资产，通过智能调度与传输优化算法安全、高效地送达目的地，并支持多团队在统一空间内协同使用同一份数据。

### 1.2 解决的问题

| 现状痛点 | 平台解法 |
| --- | --- |
| 跨云、跨地域传输慢，大文件动辄数小时 | 并行分片 + 多路复用 + 智能路由，多通道并发抢带宽 |
| 带宽成本高且不可控 | 压缩 / 去重 / 秒传 / 冷热分层，可视化成本节省 |
| 传输过程黑盒，失败了不知道为什么 | 全链路可观测：速率曲线、分片粒度、结构化日志、错误码与处置建议 |
| 多团队重复搬运同一份数据 | 协同空间 + 数据集引用，一次上传多方复用 |
| 谁传了什么、传给谁，无法追溯 | 全量审计日志 + 敏感数据识别 + 加密与水印 |
| 传输策略全靠人拍脑袋 | 策略中心 + 模拟器，参数变更前先算收益 |

### 1.3 目标用户与核心场景

| 角色 | 关注点 | 高频场景 |
| --- | --- | --- |
| 数据平台管理员 | 全局资源、容量、成本、SLA | 查看总览、配置节点与通道、审批策略 |
| 运维工程师 | 任务是否正常、故障如何定位 | 盯实时任务、处置告警、重试失败任务 |
| 数据工程师 | 数据能否按时到位 | 创建传输任务、选择策略、查看校验结果 |
| 项目 / 业务成员 | 拿到的数据是不是最新的 | 进入协同空间、浏览数据集、留言协作 |
| 安全合规 | 有没有违规外发、数据是否加密 | 查审计日志、看敏感识别结果、配访问控制 |

### 1.4 核心价值主张（需在 UI 中被反复表达）

1. **看得见**：任意时刻的传输量、速率、成功率、链路健康度。
2. **管得住**：任务、通道、策略、权限四层管控。
3. **传得快**：优化引擎带来的加速比与成本节省，用数字说话。
4. **查得清**：每一次操作都有审计留痕。

### 1.5 术语表

| 术语 | 定义 |
| --- | --- |
| 节点 Node | 参与数据传输的计算/存储单元，分为源节点、中转节点、目标节点、边缘节点 |
| 通道 Channel | 两个节点之间的一条逻辑链路，具备协议、带宽上限、QoS、加密方式等属性 |
| 任务 Task | 一次具体的数据传输作业，绑定源、目标、通道与策略 |
| 策略 Policy | 一组传输优化参数（压缩、去重、分片、并发、限速、重试、校验） |
| 协同空间 Workspace | 面向团队的数据共享单元，包含成员、数据集、动态与权限 |
| 分片 Chunk | 大文件切分后的传输单元，支持并行与断点续传 |
| 秒传 | 通过内容指纹命中已有副本，跳过实际传输 |
| SLA | 服务等级目标，本平台默认 99.95% 传输成功率 |

## 4. 详细需求

### 4.1 全局框架

**布局**：左侧固定侧边栏（展开 232px / 折叠 64px）+ 顶部 56px 工具栏 + 内容区（padding 24px，最大宽度 1680px 居中）。

- 侧边栏：深色底，顶部 Logo 与产品名，菜单按模块分组，底部显示当前版本号与"节点在线 14/16"。
- 顶部：左侧折叠按钮 + 面包屑；右侧全局搜索、通知铃铛、帮助、头像。
- 内容区顶部统一"页面头"：标题（20px/600）、一行描述（13px 次要色）、右侧主操作按钮组。
- 所有列表页统一：筛选卡片 → 工具栏 → 表格/卡片 → 分页。

**权限表现**：不同角色登录后，侧边栏模块可见性不同（成员不可见"系统设置"与"安全合规"），无权限操作按钮隐藏而非置灰。

### 4.2 登录页

- 左侧 55%：深蓝渐变背景 + 抽象数据流动线条（纯 CSS/SVG，不用外链图）+ 品牌语「让每一份数据，都在最优路径上流动」+ 三个能力点。
- 右侧 45%：白色表单卡片，居中，最大宽 380px。

## 5. 数据模型与 Mock 规范

### 5.1 通用要求

- 所有列表数据不少于 **20 条**，任务不少于 **48 条**，告警不少于 **30 条**，审计日志不少于 **80 条**。
- 数据需"像真的"：真实的云厂商区域命名、真实的协议与文件后缀、合理的数量级关系（已传 ≤ 总量、速率与耗时自洽）。
- 时间使用相对当前时间生成（`dayjs().subtract(n, 'hour')`），避免写死导致"一年前"的违和感。
- 中文姓名、企业部门、IP 段、SHA-256 片段都要真实可信。
- Mock 数据统一放在 `src/mock/` 下，按实体分文件，导出常量数组；service 层做浅拷贝后返回，避免组件修改污染源数据。

**错误码**：`ERR_CHANNEL_TIMEOUT`、`ERR_AUTH_FAILED`、`ERR_DISK_FULL`、`ERR_CHECKSUM_MISMATCH`、`ERR_SOURCE_UNREACHABLE`、`ERR_RATE_LIMITED`

### 5.4 数据自洽规则

- `transferredSize <= totalSize`；`progress = round(transferredSize / totalSize * 100)`。
- `speedBps > 0` 仅当 status 为 running/verifying。
- `durationSec ≈ transferredSize / speedBps`。
- `etaSec = (totalSize - transferredSize) / speedBps`。
- 通道 `usedMbps` 应约等于其承载 running 任务速率之和（允许 ±20% 误差）。
- 节点 `usedTB < capacityTB`，`cpu`/`mem` 在 8%-92% 之间且与负载正相关。
- 成功任务必须有 `finishedAt`，失败任务必须有 `errorCode`。

### 5.5 策略预估计算公式（前端固定实现）

```
压缩比 ratio: none=1.0, gzip=0.42, lz4=0.58, zstd=0.36（级别 1-9 线性微调 ±0.04）
去重收益 dedup: none=0, file=0.08, block=0.22
有效数据量 effective = totalSize * ratio * (1 - dedup)
并发加速 speedup = min(concurrency / 4, 6) * (chunkSizeMB >= 64 ? 1.15 : 1)
耗时 = effective / (bandwidthMbps * 0.125 * 1024 * 1024) / speedup
CPU 占用 = 12 + (压缩级别 * 3) + (dedup === 'block' ? 18 : 0) + concurrency * 0.8
节省流量 = totalSize - effective
```
结果取整并带单位，参数变化时 200ms 防抖重算。

## 6. 交互与状态规范

### 6.1 通用状态

| 状态 | 表现 |
| --- | --- |
| 加载中 | 表格用骨架屏，卡片用浅灰占位块，图表用 loading 遮罩；禁止出现空白页 |
| 空数据 | 居中插画 + 一句说明 + 引导按钮（新建/重置筛选） |
| 请求失败 | 结果区内嵌错误提示 + 重试按钮（Mock 场景可通过特殊开关触发以演示） |
| 无权限 | 403 页或操作按钮隐藏 + tooltip |
| 操作成功 | 右上角 message，2.5s 自动消失 |
| 危险操作 | Modal.confirm，红色主按钮，文案说明后果与不可撤销性 |

### 6.2 反馈原则

- 任何点击都必须有反馈：按钮 loading ≥ 300ms、行 hover 变色、可点击文字 hover 出现下划线或变色。
- 批量操作后给出结果统计：「已暂停 3 个任务，1 个任务因已完成被跳过」。
- 表单错误定位到字段下方，提交时自动滚动到第一个错误项。
- 长任务（导出、探测、保存）使用按钮内 loading，不使用全屏遮罩。

### 6.3 键盘与可达性

- `⌘K` / `Ctrl+K` 唤起全局搜索，`Esc` 关闭。
- Modal 支持 Esc 关闭（确认类除外）。
- 所有图标按钮必须有 `title` 或 `aria-label`。
- 焦点可见：不全局移除 outline。

### 8.3 关键约束（违反即视为不合格）

1. **不写任何后端代码**，不启动 server，不连接数据库。
2. **不发起真实网络请求**：不出现 `fetch`/`axios` 调用外部地址；所有数据来自 `src/mock`，经 `src/services` 包装为 `Promise`，延迟 200-600ms。
3. **不引入桌面端依赖**：不 import `electron`、`@tauri-apps/*`、`node:*`、`fs`、`path`；不使用 `window.require`、`process.env` 之外的 Node API。
4. `vite.config.ts` 必须设置 `base: './'`，产物为相对路径，可直接被桌面壳加载。
5. 路由必须使用 `HashRouter`，禁止 `BrowserRouter`。
6. 不使用 Service Worker、不依赖 CDN、不加载外部字体与图片，保证断网可用。
7. 所有 TypeScript 类型完整，禁止大面积 `any`；`npm run build` 必须零错误。
8. 不使用 `localStorage` 存业务数据（仅存 token、角色、侧边栏折叠状态）。
9. 组件单文件不超过 400 行，超出需拆分。
10. 每个页面必须有加载态与空状态。

### 8.4 桌面端打包前置说明（不实现，仅约束）

- 构建产物 `dist/` 需能在 `file://` 下正常运行：相对路径 + Hash 路由 + 无跨域请求。
- 不依赖浏览器专属能力（如 `navigator.clipboard` 需做降级 try/catch）。
- 窗口最小尺寸按 1280×720 设计。
- 不在代码中写死 `http://localhost`。
