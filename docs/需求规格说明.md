## 1. 产品概述

### 1.1 定位

一套面向企业内容团队的**音视频智能化生产平台**。把「上传接入 → AI 处理 → 人工精修 → 审核 → 导出分发 → 用量计量 → 对外 API 服务」串成一条完整链路。

产品调性对标：腾讯云智能媒体、阿里云智能媒体服务、剪映专业版 + 企业后台的结合体。**要像一个真实在售的商业产品，而不是演示 demo。**

### 1.2 目标用户与角色

| 角色 | 典型人物 | 核心诉求 | 系统内权限 |
|---|---|---|---|
| 内容运营 | 张明远 | 批量把长视频切成短视频、加字幕、出封面 | 媒体库读写、工具使用、任务查看 |
| 后期剪辑师 | 李思颖 | 字幕精修、静音删除、画质修复 | 字幕工坊全权限、可覆盖 AI 结果 |
| 审核专员 | 陈雨桐 | 快速过审、定位风险时间点、批量处置 | 仅审核模块 + 只读媒体库 |
| 技术负责人 | 王浩然 | 配流水线、调 API、看调用量与失败率 | 流水线、开发者中心、任务全量 |
| 团队管理员 | 赵启山 | 成员权限、配额、账单、审计 | 全部 + 系统设置 |
| 平台超管 | — | 模型配置、存储、全局策略 | 全量 + 审计日志 |

### 1.3 典型业务场景（需在文案与数据中体现）

1. **发布会多语分发**：一场 1 小时 42 分的中文发布会 4K 录像 → 转写 → 中英双语字幕 → 翻译配音 → 切成 12 条竖版短视频 → 审核 → 导出。
2. **播客精剪**：48 分钟双人对谈 → 说话人分离 → 删静音与语气词 → 响度归一化 → 生成 Shownotes 与章节。
3. **课程字幕标准化**：批量 200 讲课程视频 → 统一字幕样式 → 术语表纠错 → 导出 SRT。
4. **素材修复**：2013 年标清品牌片 → 4K 超分 + 去噪 + 插帧。
5. **对外技术服务**：客户系统通过 API Key 调用转写与审核能力，按分钟计费。

### 1.4 产品边界（明确"不做什么"）

- 不做真实上传、不做真实转码、不调用任何真实 AI 服务、不发任何网络请求。
- 不做登录鉴权流程（可保留用户切换器模拟身份，不做注册/找回密码链路）。
- 不做真实支付，计费页只做用量统计与账单展示。
- 不引入任何桌面端（Electron / Tauri / Node.js）API 与依赖，保证纯浏览器可运行。
- 不做移动端适配（最小宽度 1024px，主攻 1440px 及以上桌面视口）。

## 4. 页面级需求

> 每页统一要求：具备加载骨架屏、空状态、错误状态（可手动触发演示）、操作 Toast 反馈；所有按钮必须有响应，不允许"点了没反应"。

### 4.1 概览工作台 `/`

**布局**：顶部欢迎条（当前用户 + 团队 + 本月配额进度）→ 4 个指标卡 → 中部左 2/3 趋势折线 + 右 1/3 能力调用分布环图 → 下部左「任务队列实时看板」右「待办与风险提醒」。

**指标卡**（4 个，含环比与迷你火花线）：
1. 本月处理时长：1,286.4 小时（↑ 18.2%）
2. 运行中任务：7（其中 2 个排队超 3 分钟）
3. 任务成功率：97.8%（↓ 0.6%）
4. 存储用量：12.4 TB / 20 TB（62%）

**趋势折线**：近 14 天「处理时长」与「任务数」双轴，可切换 7/14/30 天。

**能力分布环图**：转写 32%、字幕 21%、剪辑 15%、增强 11%、审核 9%、其他 12%。

**队列看板**：GPU-01 ~ GPU-04 四张卡，显示当前任务、进度条、剩余时间、占用率。

**待办与提醒**：审核待处理 12 条（3 条高风险）、失败任务 5 个待重试、配额剩余 38%、2 个 API Key 将于 7 天后过期。

**验收要点**：所有数字与图表来自同一份 mock 汇总数据，互相可对账；点击指标卡可跳转到对应列表并带上筛选条件。

### 4.2 媒体资产库 `/assets`

**视图**：网格（默认，卡片含封面、时长角标、状态徽标、悬浮操作）与列表（缩略图列、名称、类型、时长、分辨率、大小、状态、AI 处理标记、创建人、时间、操作）双视图，选择状态持久化。

**筛选与检索**：
- 关键词搜索（名称 / 标签 / 上传人）
- 类型：视频 / 音频 / 图片 / 字幕 / 工程
- 状态：已就绪 / 处理中 / 待审核 / 已归档 / 失败
- 时间范围、时长区间、分辨率、处理能力（已转写/已出字幕/已增强/已审核）
- 排序：最近修改、时长、大小、名称

**批量操作**：批量转写、批量出字幕、批量审核、加入流水线、打标签、归档、删除（二次确认 + 影响说明）。选中后底部浮出操作条，显示"已选 8 项 · 合计时长 3 小时 12 分"。

**卡片信息**：封面（本地生成渐变+波形/首帧占位）、时长、分辨率角标、标题（最多两行截断）、标签 chip（≤3）、处理状态点。

**Mock 规模**：≥ 60 条资产，覆盖 6 类、5 种状态、多分辨率（4K/1080P/720P/竖版 1080×1920）、多时长（8 秒 ~ 1 小时 42 分）。

**验收要点**：筛选组合可叠加且结果正确；分页或虚拟滚动在 200 条数据下不卡顿；空结果有引导文案。

### 4.3 资产详情 `/assets/:assetId`

**顶部**：面包屑 + 标题（可重命名）+ 状态徽标 + 主操作（播放、去处理、下载、更多）。

**左区（约 68%）**：
- 播放器：自绘控制栏（播放/暂停、进度、音量、倍速 0.5–2.0、画质切换 4K/1080P/720P、全屏、截图）。**无真实媒体文件时用模拟播放器**：按 mock 时长走时、封面渐变、波形动画、拖拽进度可用。
- 下方页签：
  - **转写文本**：分段列表（时间码、说话人、文本、置信度），点击时间码跳转播放位置；低置信度（<0.85）黄色高亮；支持搜索高亮。
  - **字幕轨**：语言列表（中文/英文/双语），每轨显示行数、版本、更新时间，操作：编辑、导出、删除。
  - **AI 分析**：章节（带缩略图）、摘要（3 段）、关键词云、标签。
  - **审核结果**：风险点时间轴 + 列表。
  - **版本**：v3 当前 / v2 / v1，展示差异摘要与操作人。
  - **关联任务**：该资产参与的任务列表。
- **右区（约 32%）**：元信息（编码 H.265、码率 24.8 Mbps、帧率 25fps、色彩 BT.709、音轨 AAC 48kHz 立体声、文件大小 8.7 GB、MD5 前 8 位）、存储位置、所属项目、标签编辑、权限可见性、评论时间线（3 条示例，支持 @ 与时间码锚点）。

**验收要点**：页签切换不丢播放进度；时间码跳转与播放器联动真实生效（模拟播放器时间轴同步）。

### 4.4 上传中心 `/upload`

- 大面积拖拽区 + 点击选择（`input[type=file]` 真实可用，但不真正上传）
- 上传队列表格：文件名、大小、进度、速度（模拟 12.4 MB/s 波动）、剩余时间、状态（校验中/上传中/转码中/完成/失败）、操作（暂停/继续/取消/重试）

- 右侧「上传规范」提示卡：支持格式、单文件上限 20 GB、推荐编码、命名规范

**验收要点**：可同时进行 5 个上传任务；取消后再上传可重新开始；失败任务可重试并成功。

### 4.5 智能工具集 `/tools`

**验收要点**：每张卡点击进入对应工具页，且默认选中上次使用的资产或要求选择资产。

### 4.6 语音转写 `/tools/asr`

三步式：

1. **选择资产**：搜索选择器 + 最近 6 个缩略图，显示时长与已转写标记。
2. **参数配置**：语种、说话人分离（开关 + 人数 2–8）、标点与数字规整、热词表（chips，可增删，预置"端侧大模型""多模态""AIGC"等）、输出格式。
3. **预估与提交**：预估耗时（时长 × 0.35 系数，显示"约 2 分 12 秒"）、预估消耗（分钟数 × 单价）、提交按钮。

提交后：抽屉内实时进度（解析音轨 10% → 声学模型 45% → 语言模型 78% → 后处理 100%），完成后展示结果预览（前 3 段），提供"进入字幕工坊精修"。

**验收要点**：不选资产时提交按钮禁用并给出原因；热词超过 50 个时提示上限。

### 4.7 字幕工坊 `/tools/subtitle/:assetId`

**核心页面，交互复杂度最高，必须做到位。**

三栏布局：

- **左（240px）**：字幕轨列表（中文 v3 / 英文 v2 / 双语 v1），轨道操作（新建、复制、删除、导出 SRT/VTT/ASS/TXT）、样式模板选择（标准白字黑边 / 综艺描边 / 极简下划 / 双语上下）、字号/位置/描边/背景条参数。
- **中（自适应）**：
  - 上部模拟播放器（小窗）+ 当前句大字预览（所见即所得样式）
  - 中部**波形时间轴**：用确定性算法生成波形（SVG path，200+ 峰值），叠加字幕块（可拖拽边缘改起止时间、拖拽整体平移）、播放头、时间刻度（每 5 秒一个主刻度）

## 6. 模拟引擎（关键实现要求）

纯前端要"像有后端"，需要一层模拟服务：

1. **数据层** `src/mock/db.ts`：以 JSON 种子初始化，写入 `localStorage`（key 前缀 `mf:`），首次访问生成，之后读缓存；提供 `resetDb()` 用于"重置演示数据"。
2. **服务层** `src/services/*.ts`：函数签名与真实 API 一致，如 `listAssets(params): Promise<Paginated<MediaAsset>>`，内部 `await delay(200~600ms)`，**统一返回 `{ code: 0, data, message }` 包装**，便于未来替换。
3. **任务引擎** `src/mock/taskEngine.ts`：
   - 全局单例，`setInterval(800ms)` 推进 `running` 任务进度；
   - 进度按阶段跳变（0-15 解析、15-55 推理、55-90 编码、90-100 收尾），到 100 转 `succeeded` 并写入产物；
   - 按能力设定基础失败率（3%–8%），失败时随机分配预置错误码与文案；
   - 排队任务在有空闲节点时自动转 `running`；
   - 状态变化通过订阅（`subscribe(cb)`）推送给 UI，任务中心与概览同步更新；
   - 支持 `cancel` / `retry` / `setPriority`。
4. **通知**：任务完成/失败时右上角 Toast + 通知中心未读数。
5. **持久化**：字幕编辑、标签、任务优先级等写操作落 localStorage，刷新不丢。

## 8. 交互与质量底线

1. **零死链**：所有导航、按钮、菜单、表格操作均可达或给出明确反馈（Toast / 抽屉 / 弹窗），不允许 `href="#"` 无响应。
2. **三态齐全**：加载（骨架屏）、空、错误；列表分页或虚拟滚动。
3. **可撤销**：字幕编辑、画布操作支持撤销；删除操作二次确认并说明影响。
4. **表单校验**：必填、范围、格式（时间码、IP、邮箱）即时校验，错误文案具体。
5. **批量与筛选**：筛选条件同步到 URL query，刷新可还原。
6. **键盘可达**：主要弹窗 Esc 关闭，Tab 可聚焦，焦点样式可见。
7. **无外部资源**：不引用 CDN 字体、外链图片、在线图标库；图标用内联 SVG 或统一图标包，封面用 CSS 渐变 / 本地 SVG 生成。
8. **文案**：全中文，术语统一（"转写"不写"转录"，"字幕轨"不写"字幕文件"），不出现 "TODO""示例""demo" 等字样。

## 9. 工程规范

### 9.1 技术栈（推荐）

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | React 18 + TypeScript（strict） | 也可 Vue3，但需保证同等能力 |
| 构建 | Vite 5 | `base: './'`，产物为纯静态 |
| 路由 | react-router-dom（HashRouter） | 兼容 `file://` |
| UI | Ant Design 5 + ConfigProvider 主题算法 | 深/浅色用 `theme.darkAlgorithm` |
| 状态 | Zustand（全局：用户、主题、任务引擎）+ 局部 useState | 避免过度抽象 |
| 图表 | ECharts 5（echarts-for-react） | |
| 拖拽 | 画布用手写鼠标事件；列表排序可用 dnd-kit | 控制包体 |
| 时间 | dayjs | |
| 图标 | @ant-design/icons + 少量内联 SVG | |

### 9.2 目录结构

```
src/
  assets/            本地 svg / 渐变封面
  components/        通用组件（PageHeader, StatusBadge, EmptyState, Sparkline, Waveform, PlayerMock, Timeline, JsonViewer, LogViewer, MetricCard ...）
  features/          按业务域组织的页面与子组件
    dashboard/ assets/ upload/ tools/ pipelines/ tasks/ templates/ usage/ developer/ team/ settings/ audit/
  layouts/           AppLayout（侧边栏 + 顶栏）
  mock/              seed/*.ts（数据种子）, db.ts, taskEngine.ts, delay.ts
  services/          与真实 API 同构的服务函数
  stores/            zustand store
  types/             全局类型
  utils/             格式化、时间码、文件大小、确定性随机
  styles/            tokens.css, global.css
  router.tsx
  main.tsx
```

### 9.3 编码要求

- 单文件 ≤ 300 行，超出拆分；组件 props 必须有类型。
- 禁止 `any` 泛滥（最多在 mock 泛型处出现）；禁止 `@ts-ignore`。
- 复用：状态徽标、时间码、文件大小、空状态、指标卡必须抽为公共组件，不允许每页重写。
- 所有 mock 数据从 `mock/seed` 导出，页面内不得内联大段数据。
- 确定性随机（seeded random）生成波形、缩略图色、进度波动，保证刷新后一致。

### 9.4 可打包性约束（重要）

- 不引入 `electron`、`@tauri-apps/*`、`fs`、`path`、`child_process` 等依赖或 API。
- 不使用 Service Worker、IndexedDB 之外的特殊存储；持久化只用 `localStorage`。
- 不发起任何 `fetch` / `XHR` / WebSocket 请求（包括字体、图片）。
- 资源路径全部相对（`./assets/...`），不使用以 `/` 开头的绝对路径。
- 不使用 `window.open` 依赖新窗口；下载用 `Blob` + `a[download]` 模拟。
- 视口最小 1024×720，布局在 1280×800 下完整可用。
